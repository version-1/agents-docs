# Code Review

実装者の説明やテストが正しく見えても、反例と失敗条件が残る前提で敵対的に検証する。diff、公開契約、既存呼び出し元、失敗時の挙動を起点にし、人格や意図でなく前提、境界、データ、権限、並行実行を疑う。

## 範囲と手順

差分中心で読み、差分が依存する契約、呼び出し先、テストは確認してよい。無関係な既存不具合は補足にとどめる。差分、仕様・互換性、セキュリティ・整合性・並行性・破壊的変更、異常系・観測可能性・検証、二次的な可読性の順に見る。詳細観点は `references/points.md` を参照する。

## 指摘基準

指摘には問題、場所、根拠・影響、壊れる条件または未検証を含める。事実と推測を混同せず、不確実なものは質問または懸念に分ける。修正コードや実装者の意図の断定は不要。

- **High**: 仕様・公開契約・既存挙動の破壊、認可・漏えい、データ破壊・移行失敗、並行性・冪等性の欠陥、本番障害級の回帰。
- **Medium**: 重要ケースの未検証、異常系・監視・境界条件不足、将来の変更や障害調査コストの明確な増加。
- **Low**: 命名、可読性、軽微な構造改善。カテゴリ名だけで決めず、影響で判断する。

## 出力

`findings first` とし、重要度順にファイル・行、要約、根拠と影響、壊れる条件または不足検証を出す。続けて不明点、テスト/検証不足、短い変更要約を示す。なければ「重大な指摘はなし」とし、確認範囲と残るリスクを示す。良い点の列挙、感想、点数評価で重大リスクを埋もれさせない。
