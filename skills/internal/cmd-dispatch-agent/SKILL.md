# Dispatch Agent

自己完結した仕事を指定 agent に渡し、起動だけを報告して親を止めない。結果が必要になるまで `wait_agent` を呼ばない。

## 境界

明示依頼なら必ず起動する。明示されない場合は、曖昧な判断、複数段階の設計、広範囲編集、破壊的操作、機密情報を含む仕事には使わない。指定 agent や内容を合理的に補えなければ起動前に質問する。直近の作業を止める結果待ちを投げっぱなしにしない。

依頼には目的、対象、期待出力、許可・禁止範囲、既知の制約、完了報告を含める。編集では所有ファイル/モジュール、他者の変更を戻さないこと、検証、変更ファイル一覧も明記する。機密情報、認証情報、個人情報、不要な全文ログは渡さず、同じファイルを並行編集させない。

## 起動

ユーザー指定を優先し、なければ最も狭く合う type を選ぶ。`worker` は実装・修正・テスト、`explorer` は具体的なコード調査、`scouter` は根拠収集、`reviewer` は検証、`planner` は計画、`implementer` は計画済み実装、`documenter` は文書化、`advisor` は技術判断、`gardener` は解釈不要な Git/GitHub 操作、`default` は特定不能時に使う。利用可能な type とそのモデル契約を変えない。

必要な会話文脈があれば `fork_context: true`、独立調査で文脈漏れを避けるなら `false` を選び、`spawn_agent` を一度だけ呼ぶ（複数指定時のみ複数）。同じターンで `wait_agent` を呼ばず、親の続きがあれば進める。結果を受け取ったように書かない。

## 報告

起動後、agent ID、type、依頼要約、結果を待たず進めていることを短く報告する。複数なら同じ情報を表にする。
