# ドキュメントの目的

目的：未来の自分（または他者）が「なぜ・何が・どう使う」を最短で理解できるようにする

## 作業手順

ドキュメントを作成・更新するときは、次の順序で進める。

1. ドキュメントする内容を調査する。
2. 読み手、目的、調査結果をもとにドキュメントの構成を決定する。
3. 決定した構成に沿ってドキュメントの内容を作成する。
4. 必ずドキュメント全体を読み、次の観点でレビューする。
   - 冗長な内容がないか。
   - 重複した内容がないか。
   - 文章全体の整合性が自然か。
   - Progressive Disclosure を念頭に、ドキュメントを分割する必要がないか。
5. レビュー結果を反映する。部分的な修正に固執せず、必要であれば構成から再検討してドキュメント全体を再構築する。

## ドキュメント時の注意点

- 配置は既存の文書構成を優先し、入口は README、設計判断は ADR、運用手順は Runbook を目安にする。常時必要なエージェント向けルールは AGENTS.md、タスク固有の手順は skill に置く。
- 読み手が判断・利用するために必要な情報を優先し、詳細は必要に応じて参照先へ分ける。
- パラグラフ、改行を十分に使用し、視覚的に理解し読みやすい文章にする。
- 見出しの階層を意識して、ドキュメント全体の構造が理解しやすいようにする。
- 必要に応じてマーメイドなどの図を使用し、文章だけでは理解しにくい内容を補足する。
- 見出しのアイコンは、ユーザーの指定と既存の文書様式に合い、内容の理解を助ける場合に使用する。
