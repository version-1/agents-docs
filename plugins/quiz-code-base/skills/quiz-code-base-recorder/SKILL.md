# 大目標

定期的に、設計・レビュー時の認識と実際のコードの振る舞いのズレを見つけ、認識を修正する。そのための問題と学習履歴を整合して保持する。

## 共通ランタイム

Python 3.10以上の標準ライブラリのみを使用する。`python3 <このskillの絶対パス>/scripts/quiz.py --repo REPO COMMAND ...` を実行する。SQLや復習計算をAIで作り直さない。

- [CLI・入力契約](references/cli.md): 実行時に読む。コマンド・問題JSON・出題／回答の手順。
- [DB定義](references/schema.md): スキーマの確認・変更時に読む。
- [初期SQL](scripts/migrations/001.sql) と [v2移行](scripts/migrations/002.sql): スキーマの正本。定義変更時は既存SQLを書き換えず次の連番migrationを追加し、対応バージョンとテストも更新する。

既定DBは `~/.local/share/quiz-code-base/quiz.sqlite3`。`--db PATH` で検証用DBを指定できる。git common directory の実パスでリポジトリを識別し、ブランチ・worktree間で履歴を共有する。単独cloneやリポジトリ移動は別の学習対象になる。単一ローカルユーザー向け。

## 不変条件

- 通常の提示で出題回数を増やす。未回答は正誤・連続正解数・復習予定に影響しない。
- 初回正解は1日後、2連続正解は7日後、3連続正解で習得済み。不正解は0に戻して翌日。UTCの24時間単位で計算する。忘却曲線を参考にした運用ルールであり個人の記憶を測定するモデルではない。
- 練習は出題／回答履歴も進捗も更新しない。新規問題の保存は行う。
- 予定日前・習得済み・削除済み・旧版は自動出題しない。根拠が変われば出題・採点を止め、analyzerへ戻す。
- 回答は提示時の選択肢順で採点し、一度だけ記録。提示のスナップショットを保存する。
- 移行はバックアップ後にトランザクションで実行。未対応のバージョンや移行失敗を迂回しない。
