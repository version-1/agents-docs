# 大目標

定期的に、設計・レビュー時の認識と実際のコードの振る舞いのズレを見つけ、認識を修正する。

## 1問の対話

1. 単独呼び出しでは範囲を確認し、[入口](../quiz-code-base/SKILL.md) の選定手順を出題数1で行う。入口から選定済みIDを受けた場合はその問題を使う。
2. [recorder](../quiz-code-base-recorder/SKILL.md) の `present --id ID` を実行。保存しない場合は `--practice`。返されたJSONを一時ファイルに保持し、回答時にそのまま使う。期限前・習得済み・根拠変更時の拒否を迂回しない。
3. 問題文、A〜Dの4択、「初出」または「今回でN回目」を表示。練習では「練習・記録上の出題回数N回（更新なし）」と表示。正解・根拠・選択肢の内部IDは明かさない。
4. チャットでユーザーの回答を待つ。A〜D、1〜4、または一意に一致する選択肢の文面を表示ラベルに変換する。曖昧・無効な回答は推測して採点せず聞き直す。4択すべてを提示できる対話UIがあれば利用してよい。3択までのツールに縮めない。
5. `answer --presentation FILE --choice A` で採点する。同じ提示に二度記録しない。コード変更等で拒否されたら学習成績を更新せず理由を説明し、再解析する。
6. 正解／不正解と正答、根拠ファイル・箇所、選んだ誤答と実装の違い、設計・レビューで注意する前提を説明する。ドキュメントとの不一致があれば整合を提案するが、自動修正しない。保存時は連続正解数・次回復習日または習得済みを表示。練習では進捗未更新と伝える。

回答前に中断した場合も通常の出題回数は増えるが、連続正解数・復習日は変えない。表示に失敗した場合は黙って再提示を記録せず状況を伝える。
