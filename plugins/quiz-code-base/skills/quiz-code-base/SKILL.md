# 大目標

定期的に、設計・レビュー時の認識と実際のコードの振る舞いのズレを見つけ、認識を修正する。暗記の得点ではなく、誤った前提に気づき、次の設計・レビューで確認できるようになることを重視する。

## 入力

- 必須: コードベースの範囲（リポジトリ内のパス、複数パス、または機能名）と出題数（正の整数）。不足時だけ質問する。
- 任意: 過去の問題を含むか（既定 true）、今回の結果を保存するか（既定 true）。文字列の false を true と解釈しない。

## 進め方

1. 機能名は実在する相対パス群へ解決し、対象をユーザーに示す。出題テーマをその範囲に限定し、裏付けの関連コードは範囲外も読む。
2. [recorder](../quiz-code-base-recorder/SKILL.md) のCLI契約を読む。共通CLIを `python3 ../quiz-code-base-recorder/scripts/quiz.py` として利用する（実行時はこのskillからの絶対パスに解決）。Python標準ライブラリだけで動く。
3. `select --scope PATH ... --count N` で候補を取得。過去を含めない場合は `--new-only`。同一実行内の重複を `--exclude ID ...` で除く。変更検知された候補は [analyzer](../quiz-code-base-analyzer/SKILL.md) で再確認してから再選定する。
4. 復習期限到来を優先し、不足分は未出題の保存済み問題、さらに analyzer で作る新規問題で補う。予定日前・習得済み・削除済みは出さない。根拠の確かな問題が足りなければ実際の出題数と理由を伝える。新規問題の作成は不足数を目安に有限回で終え、同じ知識の言い換えで水増ししない。
5. [single](../quiz-code-base-single/SKILL.md) の手順で1問ずつ提示し、回答を待ち、フィードバックして次へ進む。一括で正解を明かさない。終了・中断の意思を尊重する。保存 false は全問で `--practice` を渡す。
6. 最後に回答数・正誤と、判明した認識のズレ、次のレビューで確認する観点を簡潔にまとめる。練習時は履歴未更新を明記する。

自動スケジュール登録や音声読み上げは行わない。復習間隔は次回実行時の選定に反映する。出題前に答えが分かるコード・根拠・解説を表示しない。
