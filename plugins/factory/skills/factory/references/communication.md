# 指示・連絡とエスカレーション

factory の稼働中、Pdm は追加指示の窓口であり、計画と担当への反映を担う。これは常駐監視や即時応答を保証しない。Pdm はユーザー入力または担当からのイベントを受信した時、開始・再開時、新規割り当て前、[引き継ぎと QA](handoff.md) の次の確認時点に、新着の指示と連絡を確認する。

## 指示の扱い

- ユーザーの追加指示は、既存ゴールへの補足、優先度変更、方針変更、追加ゴールのいずれかに分類する。明示された判断は計画・issue・優先度へ反映し、方針変更や達成条件の拡張に曖昧さ・未決事項がある場合だけ必要な判断をユーザーへ戻す。
- ロールからの連絡は、進捗、問題、提案、判断依頼として評価する。ロールはユーザーの指示を上書きしたり、承認・権限・品質条件を免除したりできない。
- 実行中の issue に影響する変更は、Pdm が該当 issue-runner に変更または停止を伝える。issue-runner は影響する実作業担当へ中継し、受領と停止または変更後の実状態を Pdm に返す。Pdm は次の工程を確認して状態を更新する。送信だけでは古い指示による作業が止まったと扱わない。
- 工程内のレビュー指摘と修正は issue-runner が処理する。受け入れ条件、変更範囲、依存関係、優先度、方針に影響する場合だけ Pdm に上げる。

## 役割ごとの通信契約

| 役割 | 受け取る情報 | 判断と応答 | 報告・エスカレーション |
|---|---|---|---|
| Pdm | ユーザーの追加指示、各担当の進捗・問題・提案・判断依頼 | ゴール、優先度、依存、担当、次アクションを決める。長い実装やレビューを抱えず、割り当てと停滞解消を優先する。 | 方針・達成条件の判断をユーザーへ、変更・停止を issue-runner へ伝える。受領と実状態を確認する。 |
| issue-runner | Pdm の割り当て、ユーザー指示の反映、各工程の handoff、QA の差し戻し | issue の成果物、工程、記録を完了まで管理する。工程内の修正と再検証を手配する。変更・停止を実作業担当へ中継する。 | 受け入れ条件・範囲・依存・優先度・方針に影響する事項を Pdm へ上げる。実作業担当の受領と実状態、各工程の結果と保留を Pdm・次担当へ渡す。 |
| implementer | issue-runner の受け入れ条件、変更範囲、固定 SHA、verifier の指摘 | 必要な実装・調査・検証を行い、Medium 以上の指摘を修正する。 | 成果物、検証結果、未確認点を verifier へ渡す。範囲・方針の変更が必要なら issue-runner を経由して Pdm に上げる。 |
| verifier | issue の最終差分、base/head SHA、検証結果、必要な reviewer の結果 | 検証観点と reviewer を選び、結果を一つのフィードバックに集約する。 | 修正は implementer へ、合格または未確認・保留は issue-runner へ返す。受け入れ条件やリスクが計画へ影響するときは Pdm に上げる。 |
| reviewer 群 | verifier が渡す issue、差分、SHA、検証根拠 | 担当観点で独立に確認し、指摘または省略理由を示す。 | 結果を verifier にのみ返す。実装や優先度の指示はしない。 |
| refinener | 検証済み成果物、受け入れ条件、verifier の結果 | 挙動を維持する品質改善を1巡だけ判断し、必要なら refactor・documentor を起動する。 | 改善差分または不要な理由を issue-runner と再検証担当へ渡す。仕様変更が必要なら Pdm に上げる。 |
| refactor / documentor | refinener の対象範囲、受け入れ条件、既存成果物 | 挙動維持の構造改善、または必要な文書整合を行う。 | 差分と根拠を refinener へ返す。範囲外の変更は提案として Pdm に上げる。 |
| QA | 最終成果物、受け入れ条件、検証・レビュー根拠、承認記録 | 品質、Ready 化、merge / 配布公開の承認、自動統合を別々に判定する。 | 不備は issue-runner へ返す。判定、block、owner、解除条件、次アクションを Pdm へ渡す。 |

## 連絡の記録

各連絡は、対象 issue、発信者、内容の分類、決定、担当、次アクション、確認時点を GitHub の管理 issue または作業 issue から辿れる場所に残す。割り当て・開始確認・handoff の必須項目は [引き継ぎと QA](handoff.md) に従う。停止、再開、保留、承認の記録は [進捗と承認](state.md) を正本とする。
